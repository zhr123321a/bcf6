# BCF6 signed 训练前向：论文公式及补全

本实现以论文 arXiv 2311.16121v2 §4.2、式(7)–(9)为基础，采用用户明确选择的 signed BC6H Mode 10；它不是已核实的作者代码，也不能宣称训练前向与作者逐点完全一致。纯数学原文对照位于 `bcf6/paper_formula_literal.py`，不作为训练路径。

- **端点式(7)：** 正数区间 `1 <= e <= 30` 保留 `a=31/32, b=6` 的表达式 `992*e+512`。补充符号对称：先处理绝对值、再恢复符号。signed BC6H 的零点和饱和端点分别对应 half-code 0 和 ±31743。`0..1` 与 `30..31` 用线性过渡把这些端点与论文表达式连续连接；这两段是复现补全，不是原文写出的表达式。端点参数限制为 `[-31,31]`。
- **插值式(8)：** 两区域均使用反量化后的两个端点。论文第一分支起点写为未加横线的 `e1`，这里按照两区域相同的 BC6 端点插值语义使用反量化后的端点。内部保存的索引是归一化混合权重 `t∈[0,1]`，对应式(8)中的 `2^q*x=t`。这一索引坐标选择会影响梯度尺度。
- **half 映射式(9)：** 把原式应用于中间值绝对值，再恢复符号；零点使用有梯度的分支。原文没有明确写出这一 signed 延拓。其 `floor((|y|-1)/1024)` 按论文保留，和先前的可微 half 位码线性延拓不完全相同。
- **部署仍使用标准整数解码：** 每次量化后，端点舍入、索引映射到标准权重，调用 `codec.decode_parameters` 并导出 signed Mode 10。训练连续前向与部署的整数前向不要求逐点位相同。

论文式(7)的正数仿射项与标准 BC6H 的离散零点、端点饱和处理并非完全相同，因此这里不能同时声称“对所有连续参数逐字等于论文公式”和“对所有整数输入等于标准整数解码”。本次选择在正数内部保留论文表达式，在 signed 边界作上述明确补全。是否与作者未公开训练器一致尚不可验证。

此变更改变 `model.py` 和 `source_identity()` 所覆盖的源码。历史检查点必须用原冻结源码恢复；新训练应使用新输出目录，不能混用或覆盖旧检查点。`protocol.json` 记录本实现的 `block_forward` 身份。原始模型和已有训练不自动改写。

## Linux 验证范围

- 穷举 `-31743..31743` 的 63,487 个 signed half-code 整数值，将式(9)补全后的输出与独立 FP16 位型解释逐值比较，一致；这是半精度数值映射的验证，并非整条作者训练前向的验证。
- 对所有 `[-31,31]` 的端点整数对和 8 个标准索引，共 31,752 组单通道情形，比较连续训练前向与标准整数解码。396 组逐值相同，绝对差最大 306.5；最大例子为端点 `-31,-30`、索引 `4`，连续值 `-38290.5`、整数值 `-37984.0`。这发生在极大幅值的**潜特征域**，不能当作材质域误差或训练质量测量。`|端点 code| <= 4` 的子集最大绝对差约 `7.87e-6`。
- 合成输入运行 warmup、block、finetune 各 1 步，完成 signed Mode 10 保存及独立重载。短测验证调用链，不表示论文收敛质量。
